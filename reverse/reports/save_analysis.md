## Phase 2 Update #2(2026-09)— 版面突破

### HANSAVE.DAT 版面(可驗證部分)
```
0x0000–0x063F  檔頭/資訊區:
                 - 0x00 起多行文字「君主 在 城市」(例:「劉邦 在 泗水」,行距約 0x15);
                 - 0xE8 有 "AC" 標記;
                 - ~0x140 起大量圖示樣式位元組(疑小 icon/tile)
0x0640          世界狀態副本 #0(城市表 + 人物表)
0x32B0          世界狀態副本 #1
0x5F20          世界狀態副本 #2
0x8B90          世界狀態副本 #3(檔尾前,部分)
```
- 每份狀態內容 ≈ BASEDATA.001 的 [0x540..0x2C70](即城市表 39×0x30 @ 區塊+0,人物表 255×0x20 @ 區塊+0x750),間距 = 0x2C70。
- 對 BASEDATA 做差集:
  - 副本#0(0x640):差 **1,794B** → 動態現況(資源/兵力已更動)。
  - 副本#1/#2/#3(0x32B0/0x5F20/0x8B90):各差 **~300B**,彼此幾乎相同 → 每城記錄有 1–7B 小旗標(如城市記錄 +0x09 由 00→04)。

## Phase 2 Update #4(2026-09)— 動態存檔實驗(玩家操作確認)
- **4 個 0x2C70 區塊 = 4 個存檔格**:控制實驗確認 格1→0x640、格2→0x32B0(存格2只更新 0x32B0 區塊 595B)。
  → 推測 格3=0x5F20、格4=0x8B90。header(0..0x640)為共用區,切換格子不變。
- **每回合存檔差分**:主要變動在該格城市/人物動態欄位;另有穩定候選 u16 @`0x0C5C`(格1內 0x640+0x61C)=0x0D05→06→07 隨新回合 +1。
- 已保留樣本:`dumps/save/save_turn0_newgame.dat`、`save_turn1_slot1.dat` 與工作目錄後續存檔。
- 待辦:批次推進 N 回合取樣,判斷「回合計數/月份/年份」欄位斜率。

- 例(遼東):BASEDATA 現值 0x1388(5000)/0x09C4(2500),存檔副本#0 變為 0x0C9A(3226)/0x02FA(762)… → 這些 uint32 欄位疑為兵力/資源等動態值(語意待 runtime 對齊)。

### 方法
- 以城市名編碼做 byte 精確搜尋定位各副本;以 0x30/0x20 stride 對齊;差集以 python 完成。
- 工具:`parse_save.py` → `dumps/save/save_overview.txt`。

## Phase 2 Update #3(2026-09)— 城市欄位逐欄差集
- 對 39 城 × 0x30 逐 byte 比較(BASEDATA / 存檔 #0/#1):
  - **+0x09**:39/39 城由 BASE 00→存檔 04 → 疑「城市存在/已初始化」旗標 [HYPOTHESIS]。
  - **+0x0C / +0x10 / +0x14 / +0x18 / +0x1C**(各 uint16):現況副本#0 幾乎全城變動;
    副本#1 約 1/4 城市變動 → 疑 5 個動態數值欄(兵力/錢/糧等)。
  - 前綴 +0x04..+0x0B 含城主/歸屬類欄位(現況副本 36-39/39 變動)。
- 例(遼東)現況:0x1388(5000)→0x0C9A(3226)、0x09C4(2500)→0x02FA(762)。
- 推論:存檔 #0 = 現況;副本#1/#2/#3 疑為其他快照/記錄(層數待 runtime 確認)。[HYPOTHESIS]
